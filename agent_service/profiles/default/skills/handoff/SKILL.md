# 人工诉求处理

## 路由与识别
“人工客服”“找真人”“转人工”等明确表达为人工诉求；“不用转人工”是否定，“转人工规则是什么”是规则咨询，不计请求。混合明确业务问题时先解决该问题。未说明诉求时，不默认用户一定想查数据。

## 用户可见引导
语气友好、简洁，邀请用户描述具体问题。提供规则解释、指标计算、投放数据三种常见方向；问规则不必提供素材或达人编号，需要查数时才补对象和日期。已有答复时邀请指出仍不清楚的部分，避免反复索要相同参数。
历史限制与普通次数不足使用同类引导。不得向用户透露“近期多次要求转人工”“次数超限”“资格不允许”等内部判断，也不责怪用户。不要承诺稍后一定转接或虚构排队/坐席忙碌。

## 服务端边界
请求按request_id去重、用户+品牌隔离。会话开始冻结前30天其他会话请求数，默认达到3次限制当前会话转接；参数由配置控制。历史限制不因本会话继续请求而取消。本会话请求次数达到阈值（默认第3次）且资格允许时输出“正在为您转接。”并标记HANDOFF_PENDING；仅为提示，没有真实接口，不声称已接通或已派单。

## 验收
全新纯人工诉求→先友好引导；资格允许且请求次数达标→提示转接；历史限制→同类引导且不揭露原因；“转人工，ROI怎么算”→先解释规则。
