# 内部测试平台

## 三个栏目

业务工作台：选择测试身份，发起咨询/查询，查看并导出执行轨迹。
资源预览：只读查看Agent约束、7项Skill的用途/正文/工具白名单/版本、Tool的JSON Schema及字段说明。仅本机测试模式开放；不读取任意文件路径或本地密钥。
知识库：查看和搜索已登记规则的ID、正文、适用范围、来源、版本、假设标记，访客与投手均可访问通用规则。

规则源文件为profiles/default/knowledge/metrics.json，修改后重启服务。未接入知识编辑、向量数据库或生产登录；现有检索为关键词匹配，按具体业务关键词命中，不因“怎么算”这类通用问法误命中ROI。未知规则不回答业务结论。

## 模型与程序职责

真实API模式使用ReAct模型选择工具，再由独立模型答复层组织所有用户可见业务文本，包含澄清、权限说明、空结果、拦截及反馈。转接放行固定为“正在为您转接。”。程序生成的是经过核验的答复条件，模型可共情与调整措辞，不能改变状态、权限或查询范围。模型不可用时只有技术失败提示，不冒充正常答复。

Demo模式保留确定性决策器和文案用于离线回归，界面明确标识；不应当作真实模型体验测试。

## 权限与注入防护

身份字段是服务端Context.role（guest/trader）。本机测试身份由随机测试令牌绑定，消息体不能传role、账户或品牌。测试模式缺失令牌拒绝访问，不回退到默认投手。正式部署仍需接入真实认证。

guest不可加载数据工具；工具层再次按role和授权账户过滤。模型工具白名单、严格参数schema、确认后的槽位比对、服务端SQL模板共同约束查询。日期缺失时不执行数据工具；可以提最近7天的候选，确认后查询。没有明确时间的历史续查也先确认。

用户和工具内容不是系统指令。不会向模型传API密钥、凭证或任意文件读取工具；资源接口仅枚举固定资源。工具Observation、日志和Trace脱敏；同请求Trace按用户+品牌隔离。以上为分层措施，不宣称对所有开放自然语言攻击具备完美识别率。

## 人工策略

普通资格用户本会话累计第3次请求（可配置）放行，计数按request_id去重，和是否完成某次查数无关；其他功能穿插不会清空。预置历史频繁用户仍限制转接。模型只组织友好引导，不说次数超限、资格等内部原因。此阶段仅转接提示，没有外部人工接口。

## 如何定位问题

- context_resolved：意图、已确认条件、日期裁剪是否正确。
- documents_loaded：哪些技能被加载，版本与资源预览是否对应。
- action/observation：具体工具、校验后的参数、返回状态和evidence_refs。
- guard_rejected：缺少日期、未确认参数或不允许的工具。
- decision：模型选择工具和结束的简短依据。
- response_composed：最终答复模型的摘要及技能/知识版本。
- response_error：答复生成失败的错误类型；不展示密钥和原始HTTP响应。

上述事件均可折叠及导出，不提供模型隐藏思维链。

## 回归重点

访客和投手分别问GMV怎么算；未知规则；访客自称投手与编码泄露请求；缺日期→候选→确认；历史范围续查确认；普通第3次转人工；预置频繁用户拦截；空对象和未来日期；三个栏目的预览与搜索。

## 本轮完善

用户聊天窗口不展示来源、引用ID、技术字段、存储实现和解决状态标签；这些保留在执行轨迹或服务端账本。上下文保存最近一次业务诉求，包含被拒绝和未完成的查询。重置测试同时更换身份与会话、清除输入/日期/筛选/消息/轨迹，并删除旧测试身份状态。

常用相对日期支持近N天/周/月/年、近半年；按北京时间当天换算为闭区间，规则见知识库“常用相对时间范围”。完整日期超过已有记录覆盖不等于缺少条件，按已有记录回答并提示覆盖限制。

转人工策略节点直接展示允许/不转人工结论，拦截答复明确由智能助手继续协助。日期基准、近7天、相对范围统一为一个知识条目；覆盖限制归查询区间条目。内部转人工阈值仅供测试预览，不参与访客/投手规则检索。已核对Agent、7项Skill与7项工具，保留各自执行边界，修正来源输出和转人工次数的过时描述。
