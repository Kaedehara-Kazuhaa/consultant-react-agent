## 检查方法

自动回归分两层：pytest覆盖组件、权限、并发、状态与HTTP协议；`python -m ad_agent.evals`按JSON场景逐轮核对终态、实际工具序列、关键回答及Trace闭环。固定测试基准日2026-03-26、使用合成身份和数据，避免日历变化造成假失败；不加载环境中的真实模型密钥或业务数据库。

场景文件：`evals/scenarios.json`。报告：`var/eval_report.json`（不提交运行数据）。每条检查包含场景、轮次、消息、实际状态、工具、Trace事件数、通过与失败原因。

## 基础用例

| 场景 | 验收结果 |
|---|---|
| 中文编号、寒暄混合、日期补充 | 识别M0001，先问日期，补充后定位并查日报 |
| 日期纠错 | 保留素材，仅替换日期，重新查询 |
| 规则和用法 | ROI公式/如何查询直接检索，免去无关素材追问 |
| 状态查询与越权 | A1素材显示快照；A2素材统一未找到 |
| 零值/NULL/无记录 | 各自解释，不能统一归零 |
| 部分覆盖 | 只汇总已有记录，标明缺失天数 |
| 模糊进线无后台数据 | 请求说明，不虚构最近浏览 |
| 模糊进线有上下文 | 授权、时间筛选后仅一个候选；确认才查询，否认不连猜 |
| 人工混合请求 | 先解决明确业务；纯请求不虚构交接成功 |
| 相对日期及跨话题 | 昨天/前天明确换算；规则新话题不继承旧素材 |
| 多对象/多日期 | 不任意选一个或静默取首尾 |
| 净ROI | 不用整体ROI代替净ROI |
| 正向/负向反馈 | 有效回答后的精确肯定可确认；讽刺/否定/纯引导不确认 |
| 重启、过期与并发 | 重启恢复槽位；过期不续接；同线程并发409 |
| 版本与安全 | 知识元数据与哈希可查；伪造引用、额外身份参数、未授权工具被拦截 |
