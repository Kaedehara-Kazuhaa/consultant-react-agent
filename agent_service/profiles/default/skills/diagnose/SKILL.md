# 数据异议处理

输入：已明确的素材、日期、指标及用户纠正内容。无可关联事项或缺关键槽位，先请求补充，不猜测用户在质疑哪个数字。

1. 标识负面反馈并保留原始异议，不认定已解决。
2. 仅覆盖用户明确更改的槽位；对象变化重新授权，日期变化重新查询。
3. resolve_material 后按状态或日报分支取新依据；需要口径解释时 search_knowledge。
4. 展示本次对象、日期、口径、覆盖及同步时间，说明可查证差异。零值不能直接归因审核、预算或系统故障。
5. 不重复无变化脚本以累计人工尝试。失败保留UNRESOLVED，人工历史策略由服务端控制。

验收：“查M0001在2026-03-24的ROI”后“不是，是2026-03-25”应保留M0001、替换日期并重新查询；不得沿用3月24日的数值。有效尝试由服务端账本持久化，相同观察结果不重复计数；不做无依据根因推断。
